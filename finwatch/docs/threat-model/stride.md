# 脅威モデル(STRIDE) — LLM + 外部MCP構成

信頼境界: `docs/architecture/c4.md` の境界図参照。前提: 外部MCPサーバー(EDINET DB)およびそのレスポンス(有報全文テキスト含む)は**信頼しない入力**として扱う。

| 分類 | 脅威シナリオ | 影響 | 対策 | 対応 |
|---|---|---|---|---|
| S: Spoofing | 偽MCPエンドポイントへの接続(DNS/設定改竄) | 偽データでレポート汚染、キー窃取 | エンドポイントを設定でピン留め、HTTPSのみ、URL変更はPRレビュー必須 | 実装済(registry) |
| T: Tampering | **rug pull**: サーバー側でツール定義がすり替わり、同名ツールが異なる挙動をする | 意図しない動作・データ破壊 | read-only allowlist(ADR-0006) + スキーマスナップショットdiff検知(ADR-0008) | 実装済 |
| T: Tampering | **間接prompt injection**: 有報の「事業等のリスク」全文等に敵対的指示が混入し、LLMが誘導される | allowlist外ツール呼出し試行、レポート改竄 | (1) fail-closedなツール認可 (2) ツール結果を「データ」として明示的にラップするプロンプト構造 (3) レポート出力にツール結果由来のリンク/指示文を残さないサニタイズ | 実装済/一部プロンプト対策 |
| R: Repudiation | どのツールがいつどの引数で呼ばれたか追跡不能 | インシデント調査不能 | 全ツール呼出しの構造化監査ログ(引数ハッシュ、判定結果、レイテンシ) | 実装済 |
| I: Info Disclosure | APIキーがログ・LLMコンテキスト・エラーメッセージに漏出 | キー悪用、課金被害 | 秘匿境界設計 + redact(ADR-0005)、fixtureへの実キー混入をCIで検査(secret scanning) | 実装済 |
| I: Info Disclosure | キャッシュDB(SQLite)がArtifact経由で公開流出 | 取得データの再配布(利用規約リスク) | Artifactの保持期間最小化、キャッシュにレスポンス原文でなく正規化済みデータのみ保存 | 実装済 |
| D: DoS | レート制限枯渇(100req/日)による自己DoS、外部障害 | レポート生成不能 | キャッシュ優先切替・サーキットブレーカー・stale許容(ADR-0007) | 実装済 |
| E: EoP | LLMがread-only前提を超える操作(将来サーバーに書込み系ツールが追加された場合) | データ改変 | denyがデフォルト(allowlist)。新ツールは人間レビュー経由でのみ追加 | 構造的に排除 |

## 残余リスク(受容)

- prompt injectionによる**レポート内容の偏向**(ツール悪用ではなく文面操作)は完全には防げない。緩和: 数値はLLM生成でなくツール結果から機械的に転記する構造にし、LLMは解説文のみ担当
- APIキーの長命性(OAuthを選ばなかったトレードオフ、ADR-0005)。緩和: 四半期ローテーション(runbook)
