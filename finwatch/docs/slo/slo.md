# SLI / SLO 定義

## サービス定義
「隔週(第1・第3木曜)に競合財務レポートを生成し、リポジトリにコミットする」バッチサービス。

## SLI / SLO

| SLI | 定義 | SLO | 測定 |
|---|---|---|---|
| 生成成功率 | 予定実行日の23:59までにレポートが生成された割合 | 99%(=年間26回中、失敗許容 ~0.25回 → 実質「四半期に1回未満」) | Actions実行結果 |
| データ鮮度 | レポートに使われたデータの取得時刻からの経過 | 95%のデータ項目が72h以内 | レポートメタデータ |
| 完全性 | 対象4社×主要指標のうちレポートに含まれた割合 | 90%以上(欠損は欠損と明示) | レポートメタデータ |
| ツール選択精度(品質SLI) | evalスイート合格率 | 90%以上(CIゲート、ADR-0009) | eval実行結果 |

補足: GitHub Actions cronは起動遅延があるため、SLOは「起動時刻」でなく「当日中の完了」で定義(ADR-0004)。

## エラーバジェット方針

- 生成失敗の主因は外部依存(EDINET DB / Anthropic API)。**バジェット消費が外部起因の場合**: ADR-0007のデグラデーション(staleキャッシュ生成)が機能したかを事後レビュー。機能していれば「成功(鮮度SLI消費)」に分類
- バジェット枯渇時のポリシー: 新機能(ツール追加・プロンプト変更)を凍結し、回復性改善のみ実施

## アラート

- 実行失敗 / eval閾値割れ / スキーマdiff検知 → GitHub Issueを自動起票(通知先を増やさず一元化)
